## 1. 전체 흐름 개요

```
학생 진입
    │
    ├─ [A] 신청번호 있음 ──▶ 신청번호 입력 ──▶ 채팅 입장
    │                                              │
    │                                   오퍼레이터: Seg 확인 카드
    │                                              │
    │                                   항목 활성화 (state: submitted)
    │
    └─ [B] 신청번호 없음 ──▶ 간편신청 워크플로우
                                Q1: 개통 유형 선택
                                Q2: SIM 유형 선택
                                Q3: 내용 확인 & 제출
                                    │
                                신청번호 자동 발급 (HV2026-XXXXX)
                                오퍼레이터 인트로 자동 발송 (1800ms)
                                항목 활성화 (state: empty)
```

## 2. 진입 분기 상세

### 2-A. 앱번호 경로 (기존 신청자)

**전제**: 학생이 `mobile.hirevisa.com/en`에서 신청 완료 → 신청번호 발급 받은 상태

| 단계 | 주체 | 동작 | 트리거 메시지 |
|------|------|------|-------------|
| 1 | 학생 | 신청번호 입력 (예: `HV2026-00001`) | 봇: "신청번호 [번호]가 확인되었습니다. 잠시 후 오퍼레이터가 안내해 드릴게요." |
| 2 | 시스템 | 대기 타이머 시작 (60초) | (내부) |
| 3 | 오퍼레이터 | Seg 확인 카드에서 Seg·SimType 선택 | 오퍼레이터: 인트로 멘트 (300ms 딜레이) |
| 4 | 시스템 | 항목 목록 활성화 (`state: submitted`) | (체크리스트 표시) |
| 5 | 오퍼레이터 | 각 항목 승인 / 보완요청 / 제출요청 | 상황별 자동 메시지 |

**핵심 차이점**: 신청번호 경로의 모든 항목은 `submitted` 상태로 시작.  
학생이 이미 온라인으로 서류를 제출했다고 가정하기 때문.

---

### 2-B. 워크플로우 경로 (미신청자)

**전제**: 신청번호 없음 → "신청 번호가 없으신가요?" 버튼 클릭

| 단계 | 주체 | 동작 | 화면 |
|------|------|------|------|
| 1 | 학생 | Q1: 개통 유형 선택 | 신규 번호 개통 (S1) / 기존 번호 이동 MNP (S2) |
| 2 | 학생 | Q2: SIM 유형 선택 | eSIM / uSIM |
| 3 | 학생 | Q3: 내용 확인 후 "신청 완료" 클릭 | 선택 내역 요약 카드 |
| 4 | 시스템 | 신청번호 자동 발급 (`HV2026-XXXXX`) | 봇: 신청 접수 확인 메시지 |
| 5 | 시스템 | 항목 목록 활성화 (`state: empty`) | (제출 현황 패널) |
| 6 | 오퍼레이터 | 인트로 멘트 자동 발송 (1800ms 딜레이) | (채팅에 표시) |

**핵심 차이점**: 워크플로우 경로의 항목은 `empty`로 시작.  
오퍼레이터의 Seg 확인 카드는 나타나지 않음 (학생이 Q1/Q2에서 이미 선택했기 때문).

## 5. 항목 상태 머신 (Item State Machine)

```
                 학생 제출
  empty ────────────────────────▶ submitted
    │                                  │
    │ 오퍼레이터: 제출요청              ├─ 오퍼레이터: 보완요청 ──▶ supp_requested
    │ (📋 제출 요청 버튼)               │                                  │
    ▼                                  │ 오퍼레이터: 승인                  │ 학생: 재제출
supp_requested ◀──────────────────────┤                                  ▼
    │                                  ▼                            resubmitted
    │ 학생: 재제출              approved (잠금)                           │
    ▼                                  ▲                                  ├─ 오퍼레이터: 승인 ──▶ approved
resubmitted ──── 오퍼레이터: 승인 ────┘                                  │
    │                                                                     │
    └──────────────── 오퍼레이터: 추가 보완 ──────────────────────────────┘
                                                                  supp_requested
```

| 현재 상태 | 레이블(오퍼) | 레이블(학생) | 가능한 액션 |
|---------|------------|------------|-----------|
| `empty` | 미제출 | 미제출 | 오퍼: 📋 제출 요청 / 학생: 제출 |
| `submitted` | 검토 대기 | 제출됨 | 오퍼: ✅ 승인 / 📨 보완 요청 |
| `supp_requested` | 학생 대기 | 보완 요청 | 학생: 재제출 (버튼 하이라이트) |
| `resubmitted` | 재검토 대기 | 재제출됨 | 오퍼: ✅ 승인 / 📨 추가 보완 |
| `approved` | ✓ 승인 | ✓ 승인 | 없음 (잠금) |

## 6. Case Status 자동 계산 (A/B/C/D)

> 소스: `src/lib/computeStatus.ts`  
> **Status는 절대 직접 저장하지 않음** — 항목 상태에서 실시간 파생됨.

| Status | 조건 | 우선순위 | 오퍼레이터 화면 | 학생 화면 |
|--------|------|---------|--------------|---------|
| `null` | `items.length === 0` | — | (체크리스트 비활성) | 검토대기 배지 |
| **A** | 기본값 (D·B·C 미해당) | 4 | 항목별 액션 가능 | A · 검토 중 |
| **B** | 1개 이상 `supp_requested` | 2 | 항목 "학생 대기 중" | B · 보완요청 중 + **퀵리플라이 표시** |
| **C** | 1개 이상 `resubmitted` (B 없음) | 3 | 항목 재검토 가능 | C · 재제출됨 |
| **D** | 전체 `approved` | 1 | ✅ 개통 완료 처리 버튼 | D · 개통 준비 완료 |

## 7. 자동 발송 메시지 (SCRIPT)

모든 오퍼레이터 메시지는 사전 정의된 SCRIPT에서 자동 발송됩니다.  
오퍼레이터는 `consultantMode`가 활성화된 경우에만 자유 채팅 가능.

### 7-1. 인트로 메시지

| 트리거 | 발신자 | 딜레이 |
|--------|--------|------|
| **앱번호 경로**: 오퍼레이터가 Seg 최초 확인 | 오퍼레이터(봇) | 300ms |
| **워크플로우 경로**: 학생이 Q3 완료 | 오퍼레이터(봇) | 1800ms |

```
안녕하세요, {studentName}님! 하이어비자 모바일 개통팀입니다.
신청해 주셔서 감사합니다. 아래 서류 목록을 확인하시고 순서대로 제출해 주세요.
궁금한 점이 있으시면 언제든지 말씀해 주세요. 🙏
```

### 7-2. 재제출 확인 메시지

| 트리거 | 발신자 | 딜레이 |
|--------|--------|------|
| 학생이 보완 항목 재제출 → Status가 C로 전환 | 오퍼레이터(봇) | 600ms |

```
재제출해 주신 서류를 확인하겠습니다. 잠시만 기다려 주세요. 🔍
```

> ⚠️ **조건**: `isResubmit === true && newStatus === 'C' && prev.status !== 'C'`  
> Status B에서 여러 항목이 재제출될 때, 마지막 항목 재제출로 C가 되는 시점에만 발송.

### 7-3. 전체 승인 메시지

| 트리거 | 발신자 | 딜레이 |
|--------|--------|------|
| 오퍼레이터가 마지막 항목 승인 → Status D 전환 | 오퍼레이터(봇) | 400ms |

```
모든 서류 확인이 완료되었습니다! 곧 개통 처리를 진행해 드리겠습니다. 📱
```

### 7-4. 개통 완료 메시지

| 트리거 | 발신자 | 딜레이 |
|--------|--------|------|
| 오퍼레이터가 "✅ 개통 완료 처리" 버튼 클릭 | 오퍼레이터(봇) | 즉시 |

```
{studentName}님, 모바일 개통이 정상적으로 완료되었습니다! 🎉
{segLabel} · {simLabel} 방식으로 개통 처리되었습니다.
하이어비자 모바일 서비스 이용을 진심으로 환영합니다. 😊
이용 중 불편하신 사항은 언제든지 채팅으로 문의해 주세요.
```

### 7-5. 무응답 안내 (대기 타이머)

| 트리거 | 발신자 | 딜레이 |
|--------|--------|------|
| 학생 제출/메시지 후 60초간 오퍼레이터 응답 없음 | 봇 | 60초 |

```
⏳ 곧 응대 예정입니다. 잠시만 기다려주세요.
```

> 오퍼레이터가 메시지 전송 / 항목 처리 / Seg 확인 시 타이머 초기화.

### 7-6. 보완 요청 템플릿 (항목별)

| 트리거 | 발신자 | 딜레이 |
|--------|--------|------|
| 오퍼레이터가 📨 보완 요청 버튼 → SuppModal 제출 | 오퍼레이터(템플릿) | 즉시 |

```
[보완 요청] {항목명}
{보완 사유} · {추가 안내(선택)}
```

### 7-7. 사증발급확인서 요청 (오퍼레이터 추가 항목)

| 트리거 | 발신자 | 딜레이 |
|--------|--------|------|
| 오퍼레이터가 "🛂 사증발급확인서 요청" 버튼 클릭 | 오퍼레이터(템플릿) | 즉시 |

```
[추가 서류 요청] 사증발급확인서
```

## 8. 퀵리플라이 버튼 (학생)

**노출 조건**: `status === 'B' && !consultantMode && !closed`

| 버튼 텍스트 | 타입 | 전송 메시지 | 추가 액션 |
|-----------|------|----------|---------|
| ❓ 어떤 부분이 부족한 건지 모르겠어요 | 일반 | (그대로 전송) | 없음 |
| ❓ 어떻게 제출해야 하는지 모르겠어요 | 일반 | (그대로 전송) | 없음 |
| 💬 상담사 연결이 필요해요 | 상담사 연결 | (그대로 전송) | `consultantMode = true` + 시스템 알림 발송 |

**상담사 연결 시 시스템 메시지**:
```
🔔 상담사 직접 연결이 요청되었습니다. 담당 상담사가 곧 연결됩니다.
```

**consultantMode 활성화 이후**:
- 오퍼레이터 어드민에 자유 채팅 입력창 노출
- 학생 화면 하단에 "💬 상담사 연결 중" 배지 표시
- 퀵리플라이 패널 숨김

## 9. 오퍼레이터 Seg 확인 플로우 (앱번호 경로 전용)

**조건**: `applicationNumber 있음 && !segConfirmed && !closed`

1. 오퍼레이터 어드민에 Seg 확인 카드 표시 (체크리스트 잠금 상태)
2. 4가지 버튼 중 선택:
   - S1 신규개통 · eSIM
   - S1 신규개통 · uSIM
   - S2 MNP · eSIM
   - S2 MNP · uSIM
3. 선택 즉시:
   - `segConfirmed = true`
   - 해당 Seg·SimType에 맞는 항목 목록 활성화 (`state: submitted`)
   - 오퍼레이터 인트로 메시지 발송 (300ms)
   - 대기 타이머 중지

**Seg 수동 변경** (확인 후):
- 어드민의 드롭다운에서 변경 가능
- confirm 다이얼로그 노출
- 공통 항목(`passport_scan` 등) 상태는 유지, 신규 항목은 `empty`로 추가

## 10. 개통 종료 처리

### 10-A. 개통 완료 (`closeReason: '개통완료'`)

- **조건**: `status === 'D'` (전체 승인)
- **오퍼레이터 액션**: "✅ 개통 완료 처리" 버튼 클릭
- **결과**: 완료 메시지 발송 → `closed = true`

### 10-B. 개통 취소

- **조건**: 케이스 활성 중 언제든지 가능
- **오퍼레이터 액션**: "🚫 개통 취소 처리" 버튼 → CloseModal
- **사유 선택**:
  - `개통취소-고객요청`
  - `개통취소-서류미비`
  - `기타`
- **메모**: 선택 입력

## 11. 보완 사유 카테고리

### passport_scan (여권 양면 평판 스캔본)
- 사진이 흐릿함 - 재스캔 필요
- 한쪽 면만 보임 - 양면 모두 포함 필요
- 정보 일부 가림 - 정면 재스캔
- 만료일 임박/지남 - 재발급 후 제출

### device_info (기기정보 캡처본)
- IMEI가 보이지 않음 - \*#06# 화면 재캡처
- 모델명 확인 불가 - 설정 > 일반 > 정보 화면 캡처
- eSIM 지원 여부 확인 불가 - 설정에서 eSIM 항목 포함하여 재캡처

### sim_photo (유심 사진)
- 사진이 흐릿함 - 재촬영 필요
- 유심 번호가 보이지 않음 - 번호 부분 포함하여 재촬영
- 다른 유심이 촬영됨 - 실제 사용할 유심 재촬영

### current_carrier (기존 통신사 확인)
- 문자 캡처본이 불명확함 - 재캡처 필요
- 통신사 정보가 보이지 않음
- 다른 번호의 캡처본으로 보임 - 본인 번호로 재확인

### current_number (기존 전화번호)
- 번호 형식 오류 - 올바른 번호 재입력
- 통신사 캡처본의 번호와 불일치 - 재확인 필요
- 본인 명의 아님 - 확인 필요

### visa_confirm (사증발급확인서)
- 파일이 불명확함 - 재업로드 필요
- 만료된 서류 - 최신 서류 필요
- 다른 서류가 첨부됨 - 사증발급확인서로 재제출
